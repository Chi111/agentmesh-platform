# 001 并发与状态完整性需求

来源：`docs/prd.md` v1.1 的 R-SEC-01、R-STATE-01、R-DSP-01、R-DSP-02、R-SET-01、R-EVT-01。

## 验收标准

1. 相同幂等键只有在方法、路径和规范化请求体均一致时才允许重放。
2. Agent 派发/回调只能在任务运行、托管持有且阶段可用时原子迁移；回调去重、状态、事件和进度同事务，终态不可覆盖，进度不可下降。
3. D1 在并发下只允许一个活跃争议，并保证验收与争议只有一个状态分支获胜。
4. 争议裁决只允许首个 `reviewing -> resolved|rejected` 转换产生副作用。
5. 验收结算只允许首个 `review + held -> completed + released` 转换产生副作用。
6. 请求方仅可发起固定的人工协助事件；开发者不能通过通用事件接口伪造执行状态。
7. 任务并发启动只产生一次扣款和启动事件；派单故障不能覆盖已由签名回调写入的终态。

## 保持不变

- Sepolia mUSDC / sETH 的链上校验和 `payoutHash` 规则不变。
- Web2 CREDIT 仍为不可提现测试余额，领取频率和金额不变。
- Agent 派发签名格式、Endpoint SSRF 防护和工作流锁定规则不变。
- 演示沙盒不写入 Worker 或 D1。
