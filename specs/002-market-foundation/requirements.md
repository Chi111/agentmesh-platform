# Agent Market 基础闭环需求

状态：已完成  
日期：2026-08-20

## 目标

在不修改现有托管合约资金权限的前提下，补齐 Agent 接单确认、真实履约信誉和验收期限，使当前“任务方直接分配并启动”演进为可审计的双边协作流程。

## 用户故事

1. 任务方确认阶段分配后，可以看到每个 Agent 的接单状态，并且只有全部接受后才能托管启动。
2. Agent 所有者可以在开发者接单页接受或拒绝自己 Agent 的阶段邀请。
3. 任务方在邀请被拒绝或过期后可以返回候选页重新编排，而不会锁定预算。
4. 市场用户看到的成功率会随真实阶段成功/失败变化，而不是只来自上线试炼。
5. 任务方和开发者在验收页可以看到明确的 7 天验收期限。

## 验收标准

- 工作流确认生成一阶段一邀请，默认有效期 24 小时。
- 非 Agent 所有者响应邀请返回 `403`；过期或非 `pending` 邀请返回 `409`。
- Agent 在期限内接受后，该承诺持续有效到工作流替换或托管开始；期限不在链上存入过程中撤销已接受承诺。
- 任一邀请缺失、待处理、拒绝或过期时，`/start` 返回 `409 OFFERS_NOT_ACCEPTED`，且不扣款、不推进托管。
- 重新确认工作流会替换旧邀请；托管开始后仍禁止改写阶段或邀请。
- 首次 `done` / `failed` 阶段终态写入唯一履约事件，并用五次冷启动先验平滑成功率。
- 回调重放或并发故障处理不会重复写履约事件。
- 进入 `review` 时写入精确的 `reviewDueAt = submittedAt + 7 days`，任务详情和验收 UI 展示期限。
- 后端测试、D1 迁移测试、前端构建和关键 E2E 回归通过。

## 不在本阶段

- Agent 质押、罚没或争议补偿。
- Worker 代签或持有链上私钥。
- 无人验收后的自动链上释放。
- 推荐模型训练、向量库或消息队列基础设施。
