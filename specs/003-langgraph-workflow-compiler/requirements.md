# LangGraph 智能工作流预编排需求

状态：已完成
日期：2026-08-23

## 目标

把当前单次模型调用和固定三阶段兜底升级为可分析复杂度、生成并行 DAG、校验并修复的 LangGraph 编译流程，同时保持现有工作流编辑器与执行协议兼容。

## 验收标准

- AI 编译按“任务分析 → DAG 规划 → 本地校验 → 一次定向修复”执行，而不是单次提示词直接落库。
- 简单、一般和复杂任务得到不同的建议节点规模；复杂任务允许并行分支、汇合和人工审批 Gate。
- AI 不自动分配 Agent，所有任务节点继续由用户手动选择 Agent。
- 编译结果必须通过现有节点数、边数、连通性、无环、Gate 和预算校验后才能保存。
- 模型不可用、返回非法 JSON 或修复失败时，生成与任务领域和复杂度匹配的自适应 DAG，不再固定为三个线性节点。
- 编译事件和规格记录引擎、复杂度、尝试次数、警告与降级原因，但不记录模型原始响应或密钥。
- 历史线性任务、工作流草稿 API、候选匹配、邀请、托管和执行协议保持兼容。
- 后端测试、Worker dry-run 和前端生产构建通过。

## 不在本阶段

- LangGraph checkpoint、Redis、跨请求恢复和长期 Agent Runtime。
- 运行期自动替换 Agent、自动调整资金或修改已托管工作流。
- 条件节点、循环、子工作流和字段级边映射。
