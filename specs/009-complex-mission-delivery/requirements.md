# 复杂任务成果包需求

状态：已完成
日期：2026-08-29

## 产品目标

AgentMesh 的价值是编排多个 Agent 完成复杂任务。客户最终购买的应是由多个阶段共同形成、可直接使用和验收的“任务成果包”，而不是若干孤立的 LLM 回答或内部 JSON。

## 核心要求

1. 研究、分析等中间节点的输出默认作为工作底稿和后续节点上下文，不伪装成最终客户交付物。
2. Implement 节点可以发布真实阶段制品；终结节点必须发布一个汇总整个工作流的完整任务成果包。
3. 终结节点必须读取所有已完成工作流的有界交接摘要、风险、结论和制品引用，而不只读取最后一个直接上游节点。
4. 完整成果包至少包含：总览、最终成品、分阶段工作底稿、验收标准、制品索引和 Manifest。
5. PinMe 页面默认打开完整成果包；阶段制品仍可切换查看，但不能抢占默认选择。
6. 内部运行时 JSON 继续只作为技术证据，不成为客户成品正文。
7. 不得声称执行了未实际发生的浏览、代码运行、外部验证或人工调研。
8. 平台验收页和 PinMe 成果页必须复用同一套安全 GFM Markdown 渲染规则，不得各自手写 Markdown 行解析器。

## 验收标准

- 三个及以上任务节点完成后，PinMe 最终目录包含多个工作流文件，而不只是 `deliverable.md`、`index.html` 和 `manifest.json`。
- 最终 HTML 展示阶段数量、真实制品数量、任务总览、分阶段成果和验收边界。
- 分析节点完成时不要求 PinMe AppKey，也不产生伪客户交付物。
- Implement 节点仍满足真实 artifact 门禁；终结节点自动生成最终成果包。
- 验收页默认选择终结节点的完整成果包，并明确区分“完整成果包”与“阶段制品”。
- 表格、任务列表、引用、代码块和链接在两个交付界面均可读；原始 HTML 不执行，`javascript:` 等危险链接不生成可点击地址。
- 后端单元测试、前端构建和 Worker dry-run 通过。

## 不在本期

- 为内置 Agent 增加浏览器、代码沙箱或第三方 SaaS 工具权限。
- 用篇幅或字数伪装复杂度。
- 自动部署、数据库迁移或新增云资源。
