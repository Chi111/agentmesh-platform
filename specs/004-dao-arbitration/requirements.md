# DAO 仲裁投票需求

状态：已完成
日期：2026-08-23

## 目标

将当前“单一管理员直接裁决”升级为可审计的仲裁委员会提案投票。首版实行一人一票，同时冻结并保存成员 Power 快照，为后续按 Power 加权计票保留兼容路径。

## 角色与权限

- 平台管理员可以任命或停用仲裁委员会成员；委员会身份独立于 requester、developer、admin 业务角色。
- 活跃委员会成员可以查看待仲裁案件并参与自己被纳入快照的提案投票。
- 任务方、涉案 Agent 所有者和争议发起人属于利益相关方，不得进入该案投票快照。
- 只有平台管理员可以开始审核、结束到期投票和执行通过后的资金裁决。
- 非委员会用户只能看到自己参与任务的争议和公开的提案统计，不能投票。

## 提案与投票规则

- 管理员接手 open 争议时创建唯一仲裁提案，并冻结当时的活跃、无利益冲突成员名单。
- 首版 `weightMode` 固定为 `one_person_one_vote`；每位成员计票权重为 1，同时保存 `powerSnapshot`。
- 投票选项为：支持争议方退款、驳回争议并恢复任务、弃权。
- 每个快照成员只能投一次，投票提交后不可修改。
- 默认投票期为 72 小时；法定人数为快照有效票权的 60%，向上取整且至少为 1。
- 弃权计入法定人数，不计入支持与反对的多数比较。
- 达到法定人数后，支持票严格大于反对票则授权退款，反对票严格大于支持票则授权驳回；平票或全部弃权为 `inconclusive`，不授权任何资金动作。
- 所有人已投票，或结果在数学上已不可逆时，可以提前定案；否则到截止时间后由显式 finalize 定案。
- 未达到法定人数时标记 `quorum_failed`，托管保持冻结，管理员可在后续版本发起补充提案；首版不允许绕过投票直接裁决。

## 资金与审计边界

- 投票结果只产生裁决授权，不自动退款或解冻。
- `succeeded` 提案只能执行“支持争议方退款”；`defeated` 提案只能执行“驳回争议并恢复任务”；`inconclusive` 和 `quorum_failed` 均不得执行资金动作。
- Web3 继续由管理员钱包发起合约交易，Worker 核验交易后落库；Web2 继续使用现有原子账本结算。
- 没有已定案且结果匹配的提案时，`resolve` 必须拒绝执行。
- 成员变更、提案创建、每张票、定案和执行都必须留存不可变审计记录。

## 兼容性

- 已 resolved/rejected 的历史争议保持原样。
- 处于 open/reviewing 且尚无提案的历史争议，可以由管理员初始化 DAO 提案。
- 当前管理员在迁移时自动加入仲裁委员会，Power 为 1；若利益回避后无合格成员，开始审核必须失败并给出明确提示。
- 现有托管状态、链上交易核验和并发结算保护不得弱化。

## 验收标准

- D1、MemoryStore、Worker API 和前端类型使用同一套提案与投票契约。
- 管理员可以在平台运营页任命/停用成员，但不能影响已经创建的提案快照。
- 仲裁中心展示提案生命周期、倒计时、法定人数、票数分布、投票理由和执行状态。
- 合格成员可以完成真实投票；重复投票、利益冲突、非快照成员和过期投票均被服务端拒绝。
- 直接裁决绕过投票、执行与投票结果不一致、重复执行均被拒绝。
- 后端测试、Worker 构建和前端生产构建通过。

## 不在本阶段

- ERC20/ERC721 治理代币、链上 Governor 合约和委托投票。
- 按 Power 加权计票、二次方投票和公开全平台投票。
- 多轮上诉、陪审员质押、惩罚和自动随机抽签。
- 投票通过后自动提交链上资金交易。
