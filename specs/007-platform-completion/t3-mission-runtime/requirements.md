# T3 任务运行控制需求

## 目标

在不改变已锁定的 Agent、预算、权重和托管计划的前提下，为已出资任务提供可审计的暂停/恢复、版本化返工和可重放调度检查点。

## 必须行为

- 任务方可对 `running` 且托管为 `held` 的任务执行普通暂停；管理员只能执行带原因的紧急暂停。
- 普通暂停由任务方恢复；紧急暂停只能由管理员恢复。
- 暂停的线性化点是 D1 的 outbox/stage claim。暂停生效后不得产生新的远程调用、Gate 激活或自动进入验收。
- 暂停前已 claim 的 run 视为在途。其签名终态回调可以原子落账，但不得触发后继节点、Gate 或 review。
- 恢复必须使用状态 CAS 与调度对账；重放、并发恢复和 cron 最终只能生成一个当前 attempt 的活动 run。
- 返工申请必须记录原因、验收标准、目标节点、受影响的后代节点、发起人和单调版本。
- 返工创建新 stage attempt；旧 attempt、输出、事件和交付物保留。旧 run 的迟到回调不得改变新 attempt。
- 返工命令不接受预算、Agent、权重、收款人或 payout hash 修改。这些变更必须走退款并新建任务。
- 每次暂停、恢复和返工都写入 append-only checkpoint 与执行事件。
- D1Store 和 MemoryStore 对权限、状态转移、幂等、回调与对账的表现必须一致。

## 可观察验收

- API 返回派生的 `paused` 状态、暂停模式/原因/操作人/时间、返工历史和检查点。
- 执行页按角色展示暂停、恢复和返工操作；暂停时禁用所有新调度、Gate 决策和重试操作。
- 返工表单只允许选择任务节点、原因和验收标准，不暴露资金或结算字段。
- 测试覆盖 pause/dispatch 竞态、暂停回调、并发恢复、迟到回调、版本历史、权限矩阵、迁移重放和 D1/Memory 对齐。
