# 007 平台剩余能力完善需求

状态：option 1 已批准；Wave A 执行中  
日期：2026-08-26

## 目标

完成现有 PRD、readiness 文档和 003–006 规格中明确留到后续版本的能力，同时保持当前任务托管、身份、审计、幂等和不可代签边界。该目标包含产品能力、协议升级和上线准备，但不把“代码已写”冒充独立审计、真实资金验收或生产部署完成。

## 全局约束

- 当前已通过回归的 MVP 行为保持兼容；新增能力采用迁移、版本或独立模块，不重写历史事件。
- Worker、后台任务和管理员均不得保存或代用用户、Agent、Treasury 或仲裁者私钥。
- 涉及真实资金、主网、跨链、收益策略或自动链上执行的功能，必须在独立审计、测试网演练和明确部署授权后才可启用。
- 托管生效后的收款人、权重和 `payoutHash` 不可静默修改；需要改变经济承诺时必须退款并创建新任务。
- 所有新命令具备权限校验、语义幂等、追加式审计和并发回归。
- 生产发布继续只使用 `pinme save`；本规格本身不授予部署或云资源变更权限。

## R-MSN：任务暂停、恢复与请求修改

- 运行中任务支持显式暂停和恢复；暂停必须阻止新的节点派发，但不能假装已经终止远端正在运行的 Agent。
- 暂停期间到达的合法终态回调可以落账和封存结果，但不得触发后继节点；恢复后从持久化调度检查点继续。
- 请求修改使用版本化返工请求，记录原因、目标节点、验收标准和发起人；不得覆盖历史交付、事件或反馈。
- 不改变预算和收款承诺的返工可以在原任务内执行；需要换收款人、改权重或增加预算时必须走退款/新任务流程。
- 任务方可发起普通暂停/返工；管理员只保留带原因的紧急暂停，不得借此修改任务方的资金承诺。

## R-WF：高级工作流与恢复

- 支持受限条件边、字段级映射、可复用子工作流和有上限的循环；表达式必须使用可验证 DSL，禁止任意代码执行。
- 条件求值、循环次数、映射结果和子工作流展开均写入可重放检查点。
- 以 D1 作为首个持久化检查点实现，避免在没有运营需求时引入 Redis；若未来切换外部状态服务，协议保持兼容。
- 循环必须有静态最大次数和全局执行预算；子工作流限制深度、节点总数和边总数。
- 自动换 Agent 只能发生在未派发或明确失败的节点，并继续服从质量闸门、所有者邀请和收款承诺；不得在用户无感知时换收款地址。

## R-REP：大规模导出与市场检索

- 超过 5,000 条的账目导出使用异步作业，支持进度、过期、取消、幂等重试和访问控制。
- 导出文件不得公开；下载令牌短期有效，审计中不记录账目正文。
- 市场支持语义召回和可解释重排；质量分继续是硬门槛，付费推广必须显式标记且不能绕过准入。
- Learning-to-Rank 只有在样本量、离线评估和回滚条件达到门槛后启用；数据不足时使用确定性排序。

## R-ARB：Power 仲裁、上诉与链上治理

- 仲裁支持现有一人一票模式与显式版本化的 Power 加权模式；每个提案继续冻结资格和 Power 快照。
- 支持至多一轮上诉；上诉必须有时限、理由和新的扩大委员快照，且不能覆盖原提案和投票。
- 任务争议资金动作仍受托管状态和提案结果双重约束；任何自动执行都不得要求 Worker 持有运营私钥。
- 生态治理可使用 Governor + Timelock 执行允许列表中的链上动作；任务争议与生态治理保持分域。

## R-ESC：托管 v2、超时结算与 Agent 履约保证

- 托管 v2 在链上保存验收截止时间，并提供任何人可调用的超时结算入口；冻结、已释放、已退款或未到期时必须拒绝。
- 超时结算使用存入时的确定性收款人、权重和 `payoutHash`，不能由调用者替换。
- Agent 履约保证金、罚没和补偿必须有明确资产、比例、归属、争议期和退款规则；同一资金不能同时记作任务支付、YD 奖励或 Earn 资产。
- 合约升级必须包含迁移/并存策略、角色最小化、多签/Timelock、属性测试和独立安全审计。

## R-YD：Earn Vault、真实收益与跨链

- Earn 使用独立 ERC-4626 风格 Vault，不得投资任务托管资金、Agent 保证金或未领取的 YD 奖励。
- APY 只能来自真实份额价格和已实现费用，不展示固定、预测或后台可编辑的虚构收益率。
- 收益策略使用允许列表适配器、存取限额、暂停、损失上限和 Timelock；首个真实资金策略需单独指定协议和链。
- 跨链 YD 必须指定 canonical chain、桥接协议、供应量不变量、消息重放保护、暂停与灾难恢复流程。
- 主网启用必须经过经济压力测试、合约审计、前端风险揭示和逐级限额。

## R-RUN：隔离 Agent Runtime

- 任意代码不得在控制面 Worker 内执行；容器 Runtime 使用独立隔离基础设施。
- 每次运行限制镜像来源、CPU、内存、时间、网络出口、文件大小和密钥作用域，并生成可审计运行证明。
- Runtime 与 Worker 通过短期单任务凭据通信；容器失陷不能获得项目 API Key、其他任务数据或长期回调 Secret。
- Runtime 故障不得绕过现有签名回调、交付物和质量事件协议。

- 后端、合约、前端、浏览器、并发、属性、安全和灾难恢复测试通过。
- PinMe/DS Trial v3 Endpoint 已部署并完成 shadow 观测；切换 `enforce` 需单独批准。
