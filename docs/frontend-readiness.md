# Frontend readiness

## 数据边界

- **正式工作区**：需要经 Worker 验证的 PinMe 或 Privy 会话；任务、Agent、通知、交付、验收和争议均通过 Worker 写入 D1。
- **公开目录**：未登录用户只能读取已上线 Agent 的公开资料；任务、注册、交付、结算和运营路由会要求登录。
- **官方测试 Agent**：新数据库包含研究、分析和写作 3 个可运行条目；它们由 Worker 内置运行时执行并自动提交结构化交付，不是前端 Mock。详情页展示真实 HTTPS Endpoint，并可打开查看调用契约。
- 前端不再包含本地业务 Mock、数据模式切换或可写沙盒分支。

## 已接入真实链路

1. 创建任务后进入 XYFlow DAG 画布；可由 AI 生成草稿或从空白创建，支持任务节点、人工审批 Gate、拖拽连线、撤销/重做和 Dagre 自动布局。
2. 逐任务节点手动选择 Agent、执行模式与输入输出契约；读取候选建议但不自动分配。确认后只向任务节点的第三方 Agent 所有者发送 24 小时邀请，Gate 不接单也不分账；官方测试 Agent 由平台运行时自动接单。
3. 开发者在“接单记录”中逐阶段接受或拒绝；拒绝、过期或重新选人后由任务方重新发送邀请。所有当前邀请接受前，前端和 Worker 都禁止进入托管。
4. Web2 任务从站内 CREDIT 余额锁定预算；Web3 任务由钱包完成 Sepolia mUSDC 授权托管或原生 sETH 托管，并把确定性收款人/权重哈希写入合约。资金锁定后不能重编排工作流。
5. 执行页复用只读 DAG：多个根节点并行派发，Join 等待全部前驱，失败分支只阻塞自己的后继；Gate 允许任务方批准或选择直接上游返工，失败任务必须显式重试且不会自动换 Agent。鉴权 SSE 连接失败时自动降级为 8 秒轮询。
6. 开发者提交 IPFS/HTTPS URI、内容哈希和 MIME 类型。
7. 所有阶段完成后提交任务方验收，并展示服务端生成的 7 天验收截止时间。
8. 任务方预览真实交付、确认 D1 分账或发起与存入承诺完全一致的钱包链上释放，并可先链上冻结再发起 Web3 争议。当前版本不会在验收截止后自动释放链上资金。
9. 普通用户查看自己参与任务的争议；管理员创建 DAO 仲裁提案，系统排除任务方、争议发起人和涉案 Agent 所有者后冻结委员会快照。委员一人一票，弃权只计入 60% 法定人数；只有明确多数结果才能授权管理员链上解冻或退款。
10. 阶段、交付、验收、结算和争议事件按偏好生成站内通知，并可通过 PinMe Email 投递到认证邮箱；设置页支持真实邮件通道自检。
11. 开发者收益中心使用不透明游标分页读取账户级 D1 逐笔账目，按 CREDIT / mUSDC / sETH 隔离汇总完整 12 周趋势，并可导出 UTF-8 CSV 对账单。
12. 体验用户可从 `/#/wallet/test-funds` 每 24 小时领取固定 100 CREDIT；页面同时链接 Web3 大学 mUSDC 水龙头和 Sepolia sETH 获取说明。
13. 设置页六个分类均可操作；通知、邮件、语言和时区偏好在真实工作区持久化到 D1。
14. 管理员平台运营页可搜索成员、调整任务方/开发者/管理员角色、任命独立仲裁委员，并读取服务端追加式权限审计；首版 Power 固定为 1，提案仍保存 Power 快照供后续加权计票。

## 前端工程状态

- 所有导航入口均有 React 路由，没有 iframe、空路由或 Stitch 运行时依赖。
- 全局搜索可跳转任务和 Agent；核心路由随主包交付，避免 IPFS 网关对细分路由分包的偶发不可达。Privy、Sentry 和 PostHog 仍按配置加载，不进入未启用功能的首屏执行路径。
- 配置 Privy 后，统一登录入口支持邮箱验证码、Google、SIWE 外部钱包与无钱包用户的嵌入式 Ethereum 钱包；未配置时自动回退现有 PinMe Web2 登录。
- 桌面和移动端共用响应式应用框架，侧栏底部账户区不会覆盖导航。
- 正式工作区不会显示伪造钱包余额、交付预览、收益趋势或资金流水；仲裁票数、理由、法定人数和执行状态全部来自 Worker + D1。
- API 错误、加载、空结果和权限限制均有可见状态；顶层错误边界可在渲染异常时安全重载或返回工作台。
- 关键页面有 Playwright 回归用例；Sentry 与 PostHog 仅在提供公开项目键后初始化，默认不采集输入内容或自动回放。

## 当前明确边界

- Web2 CREDIT 是站内测试记账单位，不可提现，也不代表法币或链上资产。测试充值固定为 100 CREDIT，并由服务端执行 24 小时限频。
- mUSDC 与 sETH 仅用于 Sepolia 测试网。切换合约模式前仍需完成独立合约审计、Sepolia 全链路演练、合约部署和前后端同源配置。
- 合约模式覆盖存入、验收分账、冻结、解冻和退款。请求方可冻结自己的托管资金；解冻/退款只能由 `ARBITER_ROLE` 执行，前后端只在验证链上事件后改变控制面状态。
- 第三方 Agent 计算发生在开发者 HTTPS Endpoint，Worker 负责派发、有限重试和阶段级签名回调；私有 Endpoint 凭据必须通过 Worker Secret 映射提供。官方测试 Agent 是测试网内置运行时，使用 PinMe LLM 并在失败时明确降级，不接受外部注册者伪装。
- `reviewDueAt` 目前是显式验收 SLA，不授权 Worker 代签或自动释放链上资金；Agent 质押、罚没与超时自动结算需要合约 v2 和独立审计。
- 开发者账目接口使用复合游标分页，客户端 CSV 最多自动汇总 5,000 条；超过该规模的税务报表和异步导出任务仍不在当前范围。
- “暂停任务”和“请求修改”尚未接入服务端状态机，因此当前不显示。
- 首版仲裁是一人一票的委员会治理；按 Power 加权、治理代币、委托投票、质押与上诉流程仍不在当前范围。
