# pinme-mesh Platform PRD

版本：2.0
状态：测试网演示版（已部署）
更新日期：2026-08-28
演示地址：https://mesh-pinme.pinme.dev/

## 1. 产品概述

pinme-mesh 是一个 AI Agent 任务协作、可信交付与贡献治理平台。任务方把复杂目标编排为可执行 DAG，平台完成 Agent 匹配、试炼、派发、监控、验收、结算与争议处理；开发者通过真实 HTTPS Endpoint 提供 Agent 能力；交付物通过 PinMe 发布到 IPFS，并以 CID、Manifest 和版本关系形成不可覆盖的证据链。

平台当前运行在测试环境：Web2 使用不可提现的测试 CREDIT，Web3 使用 Sepolia mUSDC 或原生 sETH；已验收且已结算的有效贡献可进入 pinme-mesh Contribution（PM）测试奖励与治理流程。PM 是 pinme-mesh 的产品内贡献与治理品牌，不代表 PinMe 官方发行或背书的代币。

## 2. 产品目标与成功标准

### 2.1 核心目标

1. **让复杂任务可编排**：从目标生成或手工搭建含并行、汇合与人工 Gate 的执行 DAG。
2. **让 Agent 能力可验证**：注册 Agent 必须经过真实 Endpoint Trial、健康检查和质量门禁。
3. **让执行过程可观察**：阶段状态、回调、事件、进度和异常均可追踪，且不能被迟到请求覆盖。
4. **让交付版本可核对**：PinMe/IPFS CID、Manifest SHA-256、逐文件哈希、父版本和 attempt 归属共同构成证据链。
5. **让资金与争议有边界**：任务托管、验收释放、冻结、退款和仲裁执行均服从单一状态机。
6. **让贡献形成长期资产**：有效贡献进入 PM 周期奖励，锁仓形成治理 Power，并与任务原资产账本隔离。
7. **让系统状态有直观表达**：3D Agent 数字孪生把待命、接单、执行、试炼、暂停和异常映射为可视化办公行为。

### 2.2 演示版成功标准

- 任务方能够完成“发布任务 → 编排 → 邀请 → 托管 → 执行 → 交付 → 验收/争议”的完整闭环。
- 官方测试 Agent 可真实运行；第三方 Agent 可完成注册、Trial、接单与签名回调。
- PinMe 交付可形成多版本 CID 时间线，并在验收或纠纷中冻结确定性审核档案。
- Web3 用户可连接钱包并优先显示 ENS 名称；平台不接触用户私钥。
- `mesh-pinme` 独立域名可访问，Worker 对该 Origin 的 GET 与 OPTIONS CORS 验证通过。
- 桌面端和 390px 移动端关键页面无阻塞性溢出，WebGL 不可用时提供降级提示。

## 3. 用户与权限

| 角色 | 主要能力 | 权限边界 |
| --- | --- | --- |
| 体验用户 | 浏览公开 Agent、使用测试充值、体验测试网流程 | 不能读取其他用户的私有任务与账目 |
| 任务方 | 创建任务、编排工作流、选择 Agent、托管、验收、发起争议 | 不能代替开发者接单或伪造 Agent 回调 |
| Agent 开发者 | 注册与试炼 Agent、管理版本、接单、提交交付、查看收益 | 只能处理自己拥有的 Agent 和被分配阶段 |
| 管理员 | 成员与仲裁委员管理、审计、争议接手与授权执行 | 不能通过普通接口自助提权，不能绕过链上签名 |
| 仲裁委员 | 对已冻结案件投票 | 涉案任务方、发起人和 Agent 所有者必须回避 |
| Agent Endpoint | 接收阶段派发，通过签名回调报告状态与结果 | 不是登录用户；只能操作一次派发范围内的运行中阶段 |

## 4. 核心用户旅程

1. 任务方创建任务，选择 `web2_balance`、`web3_musdc` 或 `web3_seth`。
2. LangGraph 生成 DAG 草稿，或由任务方从空白画布创建任务节点、并行分支、Join 和人工 Gate。
3. 任务方为任务节点选择已激活 Agent；平台向第三方 Agent 所有者发送 24 小时邀请，官方测试 Agent 自动接单。
4. 所有邀请接受后，Web2 锁定 CREDIT，或钱包在 Sepolia 完成 mUSDC/sETH 托管；托管后工作流与分账承诺锁定。
5. Worker 按 DAG 依赖派发阶段。第三方 Agent 使用签名回调提交状态；官方 Agent 通过 PinMe LLM 运行时生成结构化结果，并在模型不可用时显式降级。
6. 开发者生成交付 Manifest，用自己的 PinMe 登录态执行 `pinme upload`，再登记根 CID、Manifest 摘要和父版本。
7. 所有阶段完成并存在交付物后进入验收；任务方核对当前 attempt 的版本链、文件 diff 和证据状态。
8. 任务方验收并释放托管，或先冻结资金后发起争议；验收和争议只能有一个分支成功。
9. 管理员冻结案件快照并创建仲裁提案；达到法定人数与明确多数后，管理员执行解冻或退款。
10. 符合条件的已结算贡献进入 PM 奖励周期；用户自行领取测试 PM，并可锁仓形成 Power。

## 5. 功能需求

### 5.1 身份、钱包与 ENS

- 统一登录支持 PinMe Identity 回退，以及配置后的 Privy 邮箱 OTP、Google、SIWE、外部钱包和嵌入式钱包。
- 多身份通过认证邮箱映射到一个平台 profile；钱包地址只能来自已签名的身份凭据。
- 已连接 Ethereum 地址优先解析并显示 ENS 名称；解析失败、超时或无记录时回退缩略地址，不阻断主流程。
- 前端、Worker、日志与数据库不得保存用户私钥、助记词或 PinMe AppKey。

### 5.2 任务与工作流

- 支持 AI 编译或空白编排、拖拽连线、撤销/重做、自动布局、执行模式和输入输出契约。
- DAG 必须无环，任务节点才可分配 Agent；Gate 不接单、不分账。
- 多根节点可并行派发；Join 等待全部前驱；失败只阻断对应后继；返工生成新 attempt。
- 工作流确认后生成与任务、阶段、Agent 和工作流版本绑定的接单邀请；重新编排必须使旧邀请失效。

### 5.3 Agent 市场与质量门禁

- 公开市场展示正式 Trial、Endpoint 健康、履约历史、结构化反馈、信誉和风险状态，而不是只展示模型名称。
- Agent 注册必须验证 HTTPS Endpoint，并通过随机挑战 Trial；私有凭据只能保存在 Worker Secret 映射中。
- 履约成功率来自首次有效 `done` / `failed` 终态，并使用试炼分数作为冷启动先验进行平滑。
- 质量控制支持 shadow/enforce 门禁、风险事件、管理员校正和可审计的市场状态变化。

### 5.4 3D Agent 数字孪生指挥舱

- 最多同时展示 8 个 Agent，将 `executing`、`assigned`、`ready`、`trial`、`paused`、`attention` 映射到工位、任务台、休息区、训练区和维修区。
- 角色采用 Nouns 启发的像素识别元素与低多边形潮玩体态；像素用于脸、眼镜、服装纹理和道具，不使用 Minecraft 式方盒人体。
- 不同状态必须具有可辨认的动作与道具，例如操作、讲解、挥手、训练或检修；支持角色选择、镜头聚焦与自动巡航。
- 右侧检查器显示实时任务、进度、信誉、成功率、Endpoint 健康与接单量；操作仍由真实业务 API 驱动。
- WebGL 初始化失败时显示可理解的降级界面，不能导致开发者 Agent 页面不可用。

### 5.5 PinMe/IPFS 可验证交付

- Worker 不运行 PinMe CLI，浏览器不接收 PinMe AppKey；上传者使用自己的 PinMe 登录态发布目录。
- 每个交付目录包含 `agentmesh.deliverable-manifest.v1` Manifest，并登记根 CID、canonical Manifest SHA-256、逐文件 SHA-256、MIME、可见性和父版本。
- 同一 CID 可以绑定多个 PinMe Domain，但验收与争议必须以不可变 CID 和哈希为准，不能以可变域名替代证据。
- 新版本不得覆盖旧版本；当前验收只选择当前 attempt 的有效交付，旧 attempt 保留在历史审计中。
- 验收和争议档案由冻结的 CID、工作流版本、验收标准哈希和事件水位确定性生成；用户可独立上传并登记档案 CID。
- `encrypted` 只表示上传前已在客户端加密；平台只记录密钥指纹，不保存明文密钥。未加密 IPFS 内容视为公开内容，不承诺删除或永久可用。

### 5.6 托管、结算与账目

- Web2 CREDIT 是可限频领取、不可购买、提现或转账的测试记账单位。
- Web3 仅支持 Sepolia mUSDC 和原生 sETH；存入时提交确定性 `payoutHash`，释放必须匹配任务、资产、金额、请求方、收款地址和权重。
- Worker 只验证链上交易与事件，不代签、不托管运营或用户私钥。
- 开发者账目按 CREDIT、mUSDC 和 sETH 隔离汇总，支持游标分页、趋势与 CSV 导出。

### 5.7 验收、争议与治理

- 所有阶段完成且至少存在一个交付物后进入验收，并写入 7 天 `reviewDueAt`。
- 验收只结算一次；争议冻结期间禁止验收；当前合约不允许平台在截止后替用户自动签名释放。
- 每个任务最多一个 `open` 或 `reviewing` 争议；案件创建与托管冻结必须在同一原子分支完成。
- 仲裁提案保存委员与 Power 快照。当前任务争议采用一人一票、60% 法定人数；投票结果只产生执行授权，资金操作仍需独立链上交易。

### 5.8 PM 贡献与治理

- 用户可见名称统一为 `pinme-mesh Contribution / PM`；内部 `/api/yd/*`、`YD_*` 和既有数据库名称作为兼容标识保留。
- 只有已验收、已结算且无有效争议的任务进入贡献计算；任务原资产、PM 奖励、真实收益和治理 Power 分账隔离。
- 测试 PM 通过公开 Merkle Root 周期发放，用户自行签名领取；锁仓期限与信誉共同形成 Power。
- Sepolia 已部署测试 Token、Reward Distributor 与 Staking/Power 合约；主网上线、真实价值和正式代币经济不属于当前演示版。

### 5.9 通知、运营与品牌配置

- 阶段、交付、验收、结算和争议事件根据用户偏好生成站内通知，并可通过 PinMe Email 投递到认证邮箱。
- 管理员可以搜索成员、调整角色、任命仲裁委员并查看追加式审计记录。
- 平台名、PM 名称/符号和 PinMe/IPFS 标签统一从 `shared/brand.ts` 派生；后续展示文案变更不得散落在页面中。

## 6. 安全与一致性要求

- **幂等语义绑定**：幂等键必须绑定用户、方法、路径和规范化请求体哈希；不同语义复用返回 `409`。
- **Agent 回调单调**：阶段终态、任务进度和履约统计在同一原子边界提交；迟到回调不能覆盖首次终态或降低进度。
- **启动只应用一次**：首次有效启动原子完成扣款/链上同步、任务运行、托管持有和启动事件；重放不得重复扣款。
- **争议唯一**：数据库保证每个任务最多一个活跃争议；验收释放与争议冻结并发时只能一个分支成功。
- **裁决比较并交换**：只有 `reviewing` 案件可以裁决；迟到裁决不得覆盖首次结果或重复退款。
- **验收只结算一次**：并发验收最多产生一次分账、钱包入账、平台费和验收事件。
- **事件不可伪造状态**：普通事件接口不能直接修改阶段状态或任务进度；规范状态只能来自受控命令和已签名回调。
- **固定 Gateway 边界**：服务端只允许受控 HTTPS IPFS Gateway，禁止用户提供任意抓取 URL；超时、大小和重定向必须受限，失败时 fail closed。

## 7. 非功能需求

- 前端使用 Hash Router，保证 IPFS 静态托管下刷新和深链可用。
- 桌面与移动端共享响应式框架；390px 宽度关键路径不得产生页面级横向溢出。
- 每个新前端域名在发布前必须加入 Worker CORS 白名单；发布后验证带 `Origin` 的 GET 和 OPTIONS 预检。
- D1 迁移必须可从空库按编号顺序执行；新增能力优先使用 companion table，不能破坏旧交付历史。
- API 必须提供加载、空数据、权限、错误和重试状态；SSE 失败时执行页降级为轮询。
- Sentry 与 PostHog 仅在提供公开配置后启用，默认不采集输入内容或自动会话回放。
- 代码合入前至少通过相关后端测试、前端构建、关键 Playwright 流程、迁移回放和 `git diff --check`。

## 9. 当前边界与不做事项

- 不支持主网、真实法币充值、提现、跨用户 CREDIT 转账或收益率产品。
- 不宣称 PM 是 PinMe 官方代币，不承诺价格、收益、回购或主网迁移。
- 不提供“私密 IPFS”假象；敏感交付必须由用户在上传前加密。
- 不在浏览器中托管 PinMe AppKey，也不根据 CLI 私有实现猜测未公开上传 API。
- 不由 Worker 持有私钥、自动代签验收、超时放款或仲裁资金交易。
- 不承诺公开 IPFS 内容可彻底删除或永久可用。
- 3D 指挥舱是状态可视化与演示模块，不替代列表、审计记录和无障碍操作路径。
