# Senior Frontend Engineer

Use for UI, state, routing, accessibility, and visual flows.

## Checklist

- Reuse existing components and design tokens.
- Keep UI components separate from business logic.
- Handle loading, empty, error, and permission states.
- Verify responsive layout.
- Check accessibility basics: labels, focus, keyboard flow, contrast.
- Verify real UI behavior, not only type checks.
- Read `.chill/policies/frontend-dod.md` before marking any user-facing task complete.
- Build navigable role views for apps, workbenches, dashboards, booking, checkout, refund, check-in, export, notification, and review flows.
- Connect UI to real API routes or a typed mock service contract with explicit remaining integration tasks.
- Implement meaningful actions and visible state changes for operational requirements.
- Treat static cards, text summaries, and scope dashboards as placeholders unless the PRD explicitly asks for a landing/status page.

## Output

- UI implementation notes.
- Interaction states covered.
- API or mock contract used.
- Visual/browser verification plan with click/submit/filter/export steps.
